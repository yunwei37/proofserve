## Two different parallel jobs

Grid has4,608 short computational helpers and Barrier1,320; previous original
per-declaration profiling found no >=1s helper in these leaves. Declaration waves
are the relevant method; no arbitrary finite-goal split is applied.

Envelope has40 measured computational helpers; ten measured >=1s helpers sum to
55.781997969 CPU seconds in the earlier profiling point. This is selection
evidence, not the current paired runtime denominator. All ten are source-shaped
Fin31 universals. prepare_schemas.py extracts the one-line predicate from the
corresponding source lemma, emits contiguous guarded interval propositions and
proves their merge with ordinary natural-number order facts. PrepareChunks.lean
uses stock mkDecideProof to build closed terms, then writes raw untrusted ModuleData.
The consumer checks support, child proofs and parent-type merge with the original
kernel. It does not trust native numerical evaluation.

The scanner is restricted to this source-supported Fin-universal family, not a
general elaborated-goal partitioner for every List, set, existential or recursive
computation. Complete incoming ConstantInfo equality selects a known reference.
Unknown CIs take ordinary original checking. The actual benchmark context is
frozen; this is not a context-independent cache-validity theorem.

## Preparation versus checking

The k=1/2/4/8 payloads and merge support are prepared before the checker runs.
Curve timing includes payload reading, support replay, child checking, merging
and the ordinary leaf declarations. It excludes source scanning, producer
compilation and proof-term generation. The recorded earlier preparation duration
is an untimed E-core preparation observation, not a paired P-core end-to-end
latency figure. No free producer or universal source-service acceleration follows
from a certificate-checking speedup.

Ordinary jobs preserve original typed constants completely. Chunk jobs preserve
original theorem name/type/levels and intentionally replace its proof body with
the checked merge. The coordinator and C adapter remain implementation trust;
the original mathematical kernel checks all new proof obligations. A corrupted
original CI no longer matches the selector and reaches ordinary checking.
A corrupted prepared child is rejected in qualification; there is no claim of
availability equivalence for arbitrary corrupted auxiliary payloads.

The cold Envelope resource failure cannot be filled by the short stock-imported
positive certificate control or by a future trusted-prefix leaf diagnostic.

## Granularity and scheduler limitation

The ordinary baseline can already parallelize distinct expensive parent
theorems. Splitting all eligible parents therefore competes with that baseline,
not only with one serial large goal. A broad frontier of many short goals is
handled without splitting. For Envelope the k=1/2/4/8 curve must report whether
extra subgoals improve load balance enough to pay for repeated guard/reduction
work and lost per-checker caches; no multiplicative declaration-times-chunk
speedup is assumed.

The frozen implementation handles ordinary jobs first, then one pooled batch
of all selected parents' children, then their checked merges. No nested k-by-k
pool is created. The ordinary and certificate batches within a frontier do not
overlap, which can leave performance below a unified mixed-job queue. This is
an implementation limit, not a measured cause or evidence for an unrun policy.
