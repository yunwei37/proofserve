## Real CI failure and fix

[engine run 41975695729](https://github.com/yunwei37/proofserve/actions/runs/41975695729)
at 456f340f failed in rust job 127073893598 at 05:43:52 UTC:
source_exit_retires_background_pipe_holders_before_returning panicked at
crates/proofserve-lean/tests/process.rs:617 with
"No such process (os error 3)". Its nine other process tests passed.
The authenticated full job log is retained at
cleanup-ci-20261105/failed-rust.log. A later pass at 420dc9d6 did not remove
this race.

Linux procfs can report ENOENT before opening a retired process, or ESRCH
after it retires during a read. The fixture retirement observation now accepts
both actual disappearance errors and still requires exit/zombie within the
same two seconds. The production ProcMonitor stat reader had the same ESRCH
gap; it now treats ESRCH as absent too, allowing the existing birth-checked
retirement/pruning logic to run. EACCES, EPERM and EIO remain fatal; unrelated
inaccessibility cannot silently discard registered owned memory.

A deterministic regression passed ENOENT but failed ESRCH on the old reader
(exit 101), then passed after the correction. A second regression verifies
that access and I/O errors remain errors. The native backend status assertions,
exit deadline, zombie condition, and registered process identity checks are
unchanged. No test was skipped or assertion weakened.

Local validation: **102 Rust tests passed, 6 existing native-REPL dependency
tests ignored locally**, full workspace/all-targets/locked; cargo fmt --check
and clippy with -D warnings passed. Validation-tree sampled RSS peaked at
396.5 MiB, below the 8 GiB limit. These are correctness checks, not timing data.
Full logs and validation.json remain on the PVC. The push CI runs the separate
native-repl-contract job with --ignored; its terminal result and actual step
execution will be checked after this commit and retained in post-push-ci.json.

## Why container CI is skipped

.github/workflows/engine.yml intentionally sets container-package to
github.event_name == 'workflow_dispatch'. Normal push/PR runs execute rust,
native-repl-contract and checker-contract instead; manual dispatch qualifies
the image alone and does not publish it. Thus a skipped container job on this
push is expected, not an executed test.

The actual local container evidence is the completed frozen-e000 preview:
[qualification record](qualification-e000ed62-preview.json) and
[acceptance report](FREEZE_E000ED62.md). It records a cold image build, build-time
network-disabled smoke tests, and a standalone --network none container with
no Workspace mounts: installation, check/audit, default/strict valid fixture,
the three existing invalid-proof cases, explicit version refusal and Mathlib
service accept/reject/sorry responses all passed. Those source contexts,
image metadata, build/smoke/cleanup logs and JSON results were retained.
Docker cache deletion does not claim that a new image was tested this round.
